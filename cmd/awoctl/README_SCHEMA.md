# AWOctl Schema Integration

## Overview

The `awoctl schema` command extends the AWO ERP scaffolding tool with powerful JSON Schema to Go type generation capabilities. This integration provides a seamless workflow for converting UI schema definitions into type-safe Go structs with appropriate tags for the ERP's schema-driven architecture.

## Features

✅ **Integrated CLI Interface** - Uses existing awoctl Cobra framework  
✅ **JSON Schema Parsing** - Supports complex nested schemas with references  
✅ **UI Tag Generation** - Automatic generation of `ui:` tags from schema metadata  
✅ **Type Safety** - Complete Go struct definitions with proper field types  
✅ **Enum Support** - Generates Go constants for schema enum values  
✅ **Validation Tags** - Automatic `validate:` tag generation  
✅ **Flexible Output** - Single file or multi-file generation options  
✅ **Dry Run Mode** - Preview generation without writing files  
✅ **Verbose Logging** - Detailed progress information  

## Installation

The schema functionality is built into awoctl. Build the tool from the project root:

```bash
cd cmd/awoctl
go build -o awoctl .
```

## Quick Start

```bash
# Convert JSON Schema to Go types
awoctl schema to-go -i ./schema.json -o ./types -p generated

# Convert entire schema directory  
awoctl schema to-go -i ./docs/ui/Schema/definitions -o ./internal/types

# Preview without writing files
awoctl schema to-go -i ./schema.json --dry-run -v
```

## Command Reference

### `awoctl schema to-go`

Convert JSON Schema files to Go structs with UI tags.

**Syntax:**
```bash
awoctl schema to-go [flags]
```

**Flags:**
- `-i, --input` (required) - Input file or directory
- `-o, --output` - Output directory (default: `./internal/generated`)
- `-p, --package` - Go package name (default: `generated`)
- `--single` - Generate single combined file
- `--dry-run` - Preview only, don't write files
- `-v, --verbose` - Enable verbose output

**Global Flags (inherited from awoctl):**
- `--dry-run` - Preview what would be generated
- `--verbose` - Enable verbose output

### Build Pipeline Integration

Add to your Makefile:

```makefile
.PHONY: generate-ui-types
generate-ui-types:
	awoctl schema to-go \
		-i ./docs/ui/Schema/definitions \
		-o ./internal/ui/types \
		-p uitypes

.PHONY: generate-all  
generate-all: sqlc goa templ generate-ui-types

.PHONY: ci
ci: fmt lint test generate-all
```

### Git Hooks Integration

Pre-commit hook example:

```bash
#!/bin/sh
# .git/hooks/pre-commit

if git diff --cached --name-only | grep -E "docs/ui/Schema.*\.json$"; then
    echo "🔄 Schema files changed, regenerating types..."
    make generate-ui-types
    git add internal/ui/types/
fi
```

## Generated Code Examples

### Input Schema
```json
{
  "$id": "./ButtonSchema.json",
  "type": "object",
  "properties": {
    "text": {
      "type": "string",
      "description": "Button display text",
      "ui:label": "Button Text",
      "ui:required": true
    },
    "variant": {
      "type": "string",
      "enum": ["primary", "secondary", "success", "danger"],
      "description": "Button style variant",
      "ui:component": "select",
      "ui:label": "Button Variant"
    },
    "disabled": {
      "type": "boolean",
      "description": "Whether button is disabled",
      "ui:component": "toggle",
      "ui:label": "Disabled"
    }
  },
  "required": ["text"]
}
```

### Generated Go Code
```go
// Code generated by awoctl schema to-go. DO NOT EDIT.
// Source: ButtonSchema.json

package uitypes

// ButtonSchema represents button configuration
type ButtonSchema struct {
	Text     string `json:"text" ui:"component=text;label=Button Text;required=true" validate:"required"`
	Variant  string `json:"variant,omitempty" ui:"component=select;label=Button Variant;options=primary,secondary,success,danger" validate:"oneof=primary secondary success danger"`
	Disabled bool   `json:"disabled,omitempty" ui:"component=toggle;label=Disabled"`
}
```

### Integration with Components

```go
package atoms

import "awo/internal/ui/types"

// Use generated schema in component
func ButtonFromSchema(schema types.ButtonSchema) templ.Component {
    props := ButtonProps{
        Text:     schema.Text,
        Variant:  ButtonVariant(schema.Variant),
        Disabled: schema.Disabled,
    }
    return Button(props)
}
```

### Component Registry Integration

```go
package engine

import "awo/internal/ui/types"

func (r *SchemaComponentRegistry) RegisterGeneratedTypes() {
    // Register form schema
    r.RegisterSchemaFactory("form", func(schemaJSON string, ctx context.Context) (templ.Component, error) {
        var schema types.FormSchema
        if err := json.Unmarshal([]byte(schemaJSON), &schema); err != nil {
            return nil, err
        }
        return molecules.FormFromSchema(schema), nil
    })
    
    // Register button schema
    r.RegisterSchemaFactory("button", func(schemaJSON string, ctx context.Context) (templ.Component, error) {
        var schema types.ButtonSchema
        if err := json.Unmarshal([]byte(schemaJSON), &schema); err != nil {
            return nil, err
        }
        return atoms.ButtonFromSchema(schema), nil
    })
}
```

### Custom Type Extensions

```go
// Extend generated FormSchema
type ExtendedFormSchema struct {
    FormSchema
    
    // Custom fields
    CustomValidation map[string]interface{} `json:"customValidation,omitempty"`
    Hooks           []FormHook              `json:"hooks,omitempty"`
}

// Add methods
func (s ExtendedFormSchema) Validate() error {
    // Custom validation logic
    return nil
}

func (s ExtendedFormSchema) ToComponent() templ.Component {
    // Custom component generation
    return molecules.FormFromExtendedSchema(s)
}
```

### Enum Handling

```go
type ButtonVariant string

const (

    ButtonVariantSecondary ButtonVariant = "secondary"
    ButtonVariantSuccess   ButtonVariant = "success"
    ButtonVariantDanger    ButtonVariant = "danger"

// Use in validation
func (v ButtonVariant) IsValid() bool {
    switch v {
```

## Troubleshooting

### Common Issues

**1. Schema Parsing Errors**
```bash
# Validate JSON first
jq . ./schema.json

# Check with verbose mode
awoctl schema to-go -i ./schema.json --dry-run -v
```

**2. Import Path Issues**
```bash
# Ensure proper module structure
go mod tidy

# Check generated imports
awoctl schema to-go -i ./schema.json --dry-run | grep "import"
```

**3. Type Conflicts**
```bash
# Use different packages
awoctl schema to-go -i ./schemas1 -o ./types1 -p types1
awoctl schema to-go -i ./schemas2 -o ./types2 -p types2
```

### Debug Mode

Enable verbose logging for detailed information:

```bash
awoctl schema to-go -i ./schemas --dry-run -v
```

Shows:
- 📄 Files being processed
- 🔄 Schema parsing progress  
- ⚠️ Warnings for skipped files
- ✅ Generation success confirmations
