# Gemini Code-Assist Configuration for /db

This directory contains all database-related assets for the Awo ERP system.

## Directory Structure

-   `migration/`: Contains raw SQL migration files managed by `migrate`. Each change to the database schema requires a new `up` and `down` migration file.
-   `queries/`: Contains raw SQL queries that are used by `sqlc` to generate the type-safe Go Data Access Layer (DAL).
-   `sqlc/`: Contains the Go code generated by `sqlc`. **Do not edit files in this directory manually.**
-   `seed/`: Contains SQL scripts for seeding the database with initial data for development and testing.
-   `schema.sql`: A snapshot of the current database schema. This is for reference and is generated automatically.

## Key Conventions

1.  **Migrations are Immutable:** Once a migration is merged and applied, it must not be edited. To make further changes, create a new migration file.
2.  **RLS is Enforced:** All tables that store tenant-specific data must have Row-Level Security (RLS) enabled. Policies are defined in the migration files. See `000001_tenent.up.sql` for an example.
3.  **Use `sqlc` for all Queries:** All database access from the application should go through the `sqlc`-generated querier (`db.go`). Do not write raw SQL queries in the application code.
4.  **Name Queries Clearly:** In the `*.sql` files within `/db/queries`, use clear and consistent names for your queries (e.g., `GetUserByID`, `CreateTenant`). These names are used to generate the corresponding Go functions.
5.  **Tenant Context is Required:** All queries on tenant-scoped tables must include a `$1` or equivalent parameter for the `tenant_id` to satisfy RLS policies.

## Workflow for DB Changes

1.  **Create a Migration:** Add a new `*.up.sql` and `*.down.sql` file in `/db/migration`.
2.  **Update Schema:** Apply the migration to your local database.
3.  **Write Queries:** Add or modify queries in `/db/queries/*.sql`.
4.  **Generate Go Code:** Run `sqlc generate`.
5.  **Use the Generated Code:** Call the new functions from the `sqlc.Querier` in your application logic.
