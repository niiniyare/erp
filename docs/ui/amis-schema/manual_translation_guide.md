## WORKFLOW FOR EACH FILE

### Step 1: Preparation
```bash
# Create backup
cp output/[filename].json output/[filename].json.backup

# Open file for editing
nano output/[filename].json
```

### Step 2: Locate Chinese Text
Use error.json entries to find exact line numbers:
```json
{
  "file": "./output/[filename].json",
  "line": 123,
  "text": {
    "tag": "description", 
    "value": "指定按钮类型，支持 button、submit或者reset三种类型。"
  },
  "translation": ""
}
```

### Step 3: Manual Translation
1. **Find line 123** in the JSON file
2. **Locate the Chinese text**: "指定按钮类型，支持 button、submit或者reset三种类型。"
3. **Translate manually**: "Specifies the button type, supports button, submit, or reset."
4. **Replace in the JSON file**

### Step 4: Quality Checks
- ✅ **Preserve JSON structure** - No syntax errors
- ✅ **Keep code intact** - Don't translate variable names, function signatures
- ✅ **Consistent terminology** - Use same English terms for repeated Chinese words
- ✅ **Context appropriate** - Consider UI/UX context

### Code Preservation Rules
1. **Keep HTML/CSS classes**: `className`, `style` attributes
2. **Preserve function signatures**: `(param: type) => boolean`  
3. **Maintain JSON structure**: Proper quotes, commas, brackets
4. **Don't translate**: Variable names, API endpoints, enum values

## QUALITY ASSURANCE

### Before Marking File Complete:
1. ✅ **JSON validates**: `python3 -m json.tool [filename].json > /dev/null`
2. ✅ **Chinese text removed**: Only English remains  
3. ✅ **Code preserved**: Function signatures intact
4. ✅ **Consistent terms**: Same translations for repeated words
5. ✅ **Context appropriate**: Makes sense in UI context

### Common Pitfalls to Avoid:
- ❌ Breaking JSON syntax with unescaped quotes
- ❌ Translating variable names or code
- ❌ Inconsistent terminology across files
- ❌ Losing technical context in translations
- ❌ Forgetting to update progress tracking
